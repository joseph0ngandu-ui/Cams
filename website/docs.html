Cams Reference

Everything you need to set up, configure, and extend the Cams wireless camera system.

Getting Started

Cams is a two-component system: an iOS app that captures and encodes video, and an OBS Studio plugin that receives and decodes it. They communicate over a custom UDP protocol on your local Wi-Fi network.

info

Cams requires both the iOS app and the OBS plugin to be on the same local network (same Wi-Fi router). Cross-subnet and VPN configurations are not currently supported.

Requirements

iOS App
  • iOS 16.0 or later
  • iPhone 12 or later (for HEVC hardware encoder)
  • Camera access permission
  • Local network access permission
  • iPad with Ultra Wide camera (for hardware Center Stage)
OBS Plugin
  • OBS Studio 30.0 or later
  • macOS 13+ / Windows 10+ / Ubuntu 22.04+
  • FFmpeg (for build) — Homebrew on macOS
  • CMake 3.20+ and a C++17 compiler

Quick Start

  1. 1

    Install the iOS app

    Download Cams from the App Store. Grant camera and local network permissions when prompted.

  2. 2

    Install the OBS plugin

    Download obs-cams from the GitHub Releases page and place it in your OBS plugins directory.

    # macOS
    ~/Library/Application Support/obs-studio/plugins/

    # Windows
    %AppData%\obs-studio\plugins\

    # Linux
    ~/.config/obs-studio/plugins/
  3. 3

    Add a Cams source in OBS

    In OBS, click the + button under Sources, choose Cams, and click OK. The plugin immediately starts browsing for devices.

  4. 4

    Open Cams on your iPhone

    Select a quality preset and tap Start Streaming. Within a few seconds, the status pill should turn emerald: OBS LINKED.

Controls & UI

center_focus_strong

Focus Lock

Tapping locks the camera focus at the current focal plane. The button turns amber and an LED indicator lights. OBS can also remotely toggle focus lock via the control channel — the button shows a distinct dashed emerald ring for remote-originated state.

wb_sunny

Exposure Lock

Locks exposure at the current value, preventing the camera from automatically adjusting to lighting changes. Identical remote control behavior to Focus Lock.

person_search

Subject Tracking

On supported iPads, uses hardware Center Stage. On all other devices, the CenterStageEngine uses VNDetectHumanRectanglesRequest with exponential smoothing (α=0.15) and a Metal-backed CIContext for crop/scale. OBS can toggle this remotely.

All presets use a 2-second GOP, CABAC entropy for H.264, MaxAllowedFrameQP=40 for HEVC, and AllowTemporalCompression=true. The quality selector is locked while streaming.

Telemetry HUD

The Telemetry HUD appears automatically when streaming begins. All three metrics update on a 1-second rolling window.

7.4 Mbps

Actual bytes sent, averaged over 1 second. Changes immediately when thermal throttle engages.

Packet Drops/Sec
0 drops/s

Increments when backpressure causes a whole frame to be dropped. Turns amber if value exceeds 0.

NOMINAL

Nominal/Fair = white. Serious = amber (bitrate halved). Critical = red (bitrate quartered).

OBS Plugin

Installation

The plugin ships as a shared library (obs-cams.so / obs-cams.dll / obs-cams.plugin). Place it in your OBS plugins directory and restart OBS.

Remote Control from OBS

The OBS plugin exposes control buttons in the source properties panel:

  • Center Stage — toggles subject tracking on the iOS device. The iOS UI updates immediately with a distinct emerald-dashed ring indicating OBS origin.
  • Request Keyframe — sends an immediate IDR frame request. Useful when cutting between camera sources.
  • Focus / Exposure Lock — locks or releases the AVCaptureDevice modes remotely.
  • Quality Preset — switches between Low, Medium, and High while streaming. The iOS quality selector reflects the change immediately.

Wire Format

Every UDP packet on port 8888 begins with a 21-byte big-endian fixed header, followed by raw NAL unit bytes.

// CamsPacketHeader — 21 bytes total, all fields big-endian
struct CamsPacketHeader {
  UInt32 sequenceNumber; // bytes 0–3 — per-frame, shared by all fragments
  UInt64 timestamp; // bytes 4–11 — nanoseconds, mach_absolute_time
  UInt8 frameType; // byte 12 — see FrameType enum
  UInt16 fragmentIndex; // bytes 13–14 — 0-based, validated < fragmentCount
  UInt16 fragmentCount; // bytes 15–16 — max 256 (kCamsMaxFragmentsPerFrame)
  UInt32 payloadLength; // bytes 17–20 — byte count of NAL payload following header
};
warning

Protocol sync requirement: CamsProtocol.swift and CamsPacket.h are the two halves of the wire format definition and must be kept in sync at all times. Any change to the header layout, frame type values, or control command values requires updating both files simultaneously.

Frame Types

Value Name isVideoData Description
0x00 h264 ✓ H.264 inter (P/B) frame
0x01 hevc ✓ HEVC inter frame
0x02 parameterSets ✓ SPS/PPS (H.264) or VPS/SPS/PPS (HEVC)
0x03 keyframe ✓ IDR / intra-coded (I-frame)
0x04 eos ✗ End of stream sentinel

Control Commands

Control packets are sent on UDP port 8889. Each packet begins with a 1-byte command identifier, optionally followed by a payload.

Byte Command Direction Payload Effect
0x00 ping bi-dir none Responds with pong (0x00)
0x01 lockFocus OBS → iOS none Sets AVCaptureDevice focus to .locked
0x02 unlockFocus OBS → iOS none Returns to continuousAutoFocus
0x03 lockExposure OBS → iOS none Sets exposure mode to .locked
0x04 unlockExposure OBS → iOS none Returns to continuousAutoExposure
0x05 requestKeyframe OBS → iOS none Forces immediate IDR frame output
0x06 setQualityLow OBS → iOS none Applies 720p 30fps 4 Mbps preset
0x07 setQualityMedium OBS → iOS none Applies 1080p 30fps 8 Mbps preset
0x08 setQualityHigh OBS → iOS none Applies 4K 60fps 50 Mbps preset
0x0A setCenterStageEnabled bi-dir 0x01/0x00 Enables or disables subject tracking

Fragmentation

Encoded frames larger than the fragment payload size (1400 bytes) are split into multiple UDP packets. All fragments for one frame share the same sequenceNumber.

  • fragmentIndex is 0-based and must be strictly less than fragmentCount.
  • Maximum fragments per frame: 256 (kCamsMaxFragmentsPerFrame). Frames exceeding this limit throw a CamsPacketisationError.tooManyFragments.
  • The OBS FrameReassembler waits up to 1000ms for all fragments. If any are missing, it fires a LossCallback and requests a keyframe.

Build from Source

iOS App

# Generate Xcode project and build (no code signing)
cd CamsApp
xcodegen generate
xcodebuild -project Cams.xcodeproj \
  -scheme Cams \
  -configuration Debug \
  -destination 'generic/platform=iOS' \
  build CODE_SIGNING_ALLOWED=NO

# Run SwiftPM unit tests (CamsCore target only)
swift test

OBS Plugin — macOS

cd obs-plugin
cmake -B build \
  -DOBS_SDK_ROOT=/path/to/obs-studio \
  -DFFMPEG_ROOT=/opt/homebrew
cmake --build build --parallel
cmake --install build

# Install installs to ~/Library/Application Support/obs-studio/plugins/

OBS Plugin — Windows

cmake -B build -A x64 \
  -DOBS_SDK_ROOT="C:\obs-studio" \
  -DFFMPEG_ROOT="C:\ffmpeg"
cmake --build build --config Release
cmake --install build --config Release

Running Tests

Swift Tests (CamsCore)
cd CamsApp
swift test
# Expected: 21 tests passed

Covers CamsProtocol.swift and NetworkTransport.swift. iOS-framework-dependent files are excluded from the package target.

C++ Tests (standalone)
cmake -S . -B build \
  -DBUILD_PLUGIN=OFF \
  -DBUILD_TESTS=ON
cmake --build build
ctest --test-dir build \
  --output-on-failure
# Expected: 144 tests passed

Runs all C++ tests without requiring OBS or FFmpeg. Includes protocol serialization, jitter buffer, reassembler, and loss callback tests.

FAQ

OBS doesn't find my device. What do I check? expand_more
  • Ensure both devices are on the same Wi-Fi network (same router / SSID). Most Wi-Fi routers block mDNS between VLANs.
  • Check that the iOS app has Local Network permission in Settings → Privacy → Local Network.
  • Make sure no firewall is blocking UDP port 8888 on the macOS/Windows machine.
  • If using a managed network (corporate, university), mDNS/Bonjour may be disabled. Use a personal hotspot instead.
The stream freezes and then recovers. What's happening? expand_more

This is typically a packet loss event. The FrameReassembler waits up to 1 second for missing fragments before dropping the frame and requesting a new keyframe. The stream resumes automatically on the next IDR frame.

Check the Drops/s counter in the TelemetryHUD. If it's consistently non-zero, move closer to your Wi-Fi router or reduce the quality preset.

Why does the bitrate drop automatically? expand_more

Two mechanisms can reduce bitrate:

  • Thermal throttling: iOS monitors device temperature continuously. At Serious thermal state, bitrate is halved; at Critical, it's quartered. The Thermal readout in the HUD shows the current state.
  • Network backpressure: If the NWConnection send queue fills up (indicating the network can't keep up), the encoder drops whole frames. The Drops/s counter increments.
Does Center Stage work on all iPhones? expand_more

Hardware Center Stage (AVCaptureDevice.isCenterStageEnabled) requires an iPad with an Ultra Wide front camera (iPad Pro M1 and later, iPad Air M1 and later).

On all other devices — including all iPhones — CenterStageEngine automatically falls back to the software path: VNDetectHumanRectanglesRequest with α=0.15 exponential smoothing, dispatched on a background Vision queue.

Can I use Cams over 5G or a cellular connection? expand_more

Not currently. Cams uses Bonjour for zero-config discovery, which requires mDNS on the local network. Cellular and cross-internet routing would require a separate signaling mechanism. This is on the roadmap as a future feature.

Thermal Throttling

iOS reports four thermal states via ProcessInfo.thermalState. Cams responds automatically:

NOMINAL
No action. Full bitrate.
FAIR
No action. Full bitrate.
SERIOUS
Bitrate reduced by 50%. HUD turns amber.
CRITICAL
Bitrate reduced by 75%. HUD turns red.
